## 1. Project Overview

Screen-AI is a **local/offline AI PC operator** — a phone-controlled agent that scans the Windows screen, receives text commands from a mobile phone, classifies intent and risk, routes to tools (file, browser, system, auth, screen, download), requires phone approval for dangerous actions, quarantines (not destroys) files, stores passwords in an encrypted vault (AES-256-GCM + Argon2id), and distills a heavy cloud teacher model (OmniParser v2) into a tiny YOLO/ONNX student for local inference.

### Three Top-Level Modules

```
1. screen_element_scanner/         — standalone screen scanner (the "eyes")
2. hackathon_ui_operator_distill/  — model distillation pipeline (cloud teacher → local student)
3. ai_pc_operator/                 — main product: FastAPI server + mobile remote + agent brain + runtime engine
```

### Data Flow Summary

```
Phone → REST/WebSocket → FastAPI Server → Agent Router → Runtime Engine → Tools → Windows PC
                                    ↕            ↕              ↕              ↕
                              Security Layer  Tier Manager  Resource Budget  Screen Scanner
                              (risk/perm/     (RAM-aware    (psutil memory   (UIA + OpenCV)
                               vault/approval) tier select)  measurement)
```

**The 11-step runtime pipeline**:
```
1.  _save_command()                           → command_id
2.  planner.classify_intent(text)             → "delete_files"
    AND asyncio.to_thread(resource_budget.measure)  ← parallel RAM snapshot
3.  risk_classifier.assess(text, intent)      → risk 0-5
    AND heatmap.hot_models_for_intent(intent) ← parallel model lookup
    AND tier_manager.decide(intent, budget, hot_models) → TierDecision
    AND model_registry.prefetch(prefetch_models)      ← parallel model load
    AND _prefetch_hot_tools(hot_tools, budget)        ← parallel tool warmup
4.  permission_engine.requires_approval(risk_level, intent) → bool
5.  if needed: approval_manager.create + wait_for_approval(timeout=300)
6.  planner.create_plan(text, intent)         → {steps: [{tool, args}]}
    AND heatmap.record_plan(intent, steps)    ← learn tool patterns
    AND screen_cache.write_json(...)          ← cache plan metadata
7.  for step: _execute_tool()                 → tool results (async or IOPool)
    + break if emergency_stopped
8.  verify all succeeded
9.  format response + runtime tier_decision.to_dict()
10. update command status
11. memory.add() + _maintenance() (unload idle)
```

**LLM fallback**: When rule planner returns "unknown" AND RAM allows nexa.5b-q4 AND model is loaded → `LLMPlanner.create_plan()` generates a tool plan from the local GGUF model.

## 7. Security Layer

### 7.1 `security/risk.py` (80 lines)

Precompiled regex patterns stored as class-level `RISK_PATTERNS`. `assess()` is async. Returns max of pattern risk and intent-based risk.

| Level | Patterns |
|-------|----------|
| 5 | "permanently delete", "wipe", "format", "export password" |
| 4 | "delete/remove all", "empty recycle bin", "admin", "system modify" |
| 3 | "login/sign in", "send email", "install", "run script" |
| 2 | "download", "rename", "move", "copy" |
| 1 | "open app/website" |
| 0 | "check/show/list", "search" |

### 7.2 `security/permissions.py` (71 lines)

`requires_approval(risk_level, intent, tool, target)` → True if risk >= 3, tool in ALWAYS_APPROVAL set, or protected path.

### 7.3 `security/pairing.py` (118 lines) — Legacy

6-digit code generation (5min expiry) → device pairing (UUID + SHA-256 token hash) → verification (hash comparison) → revocation.

### 7.4 `security/pairing_v2.py` (481 lines) — NEW

**Enhanced pairing with 4 subsystems**:

| Subsystem | Methods | Purpose |
|-----------|---------|---------|
| **QR Code Pairing** | `create_qr_pairing()`, `complete_qr_pairing()` | X25519 keypair → QR payload → phone scans → shared secret → encrypted token |
| **Device Trust** | `trust_device()`, `is_trusted()`, `auto_repair_trusted()` | Persistent pairing (30 days), auto re-pair without code entry |
| **Token Rotation** | `rotate_token()` | Issues new token, invalidates old, records audit in token_rotations |
| **Biometric Challenge** | `create_biometric_challenge()`, `verify_biometric_challenge()` | Challenge-response for vault unlock (Windows Hello / phone biometric) |

**QR payload format**: `{v:1, pid, pk:X25519_pubkey, exp, nonce, sig:HMAC}`
**Crypto**: X25519 key exchange → SHA-256 shared secret → AESGCM encrypt session token
**DB tables used**: pairing_sessions, devices (trust_until, device_public_key columns), token_rotations, biometric_challenges

### 7.5 `security/vault.py` (216 lines)

**Crypto**: AES-256-GCM + Argon2id (preferred) or PBKDF2-HMAC-SHA256 (fallback). 5-min session. Memory wipe on lock. Per-unlock derived key cache keyed by salt. Idempotent credential insert via SQLite upsert.

### 7.6 `logs/redactor.py` (68 lines)

Precompiled regex patterns for: passwords, tokens, API keys, credit cards, SSNs. Dict recursion with sensitive key detection. Now **wired as a logging filter** in main.py.

## 16. Security Model Summary

```
Layer 1: DEVICE PAIRING
  Legacy: 6-digit code (pairing.py) — 5-min expiry
  V2: QR code (pairing_v2.py) — X25519 keypair, 2-min expiry, HMAC signature

Layer 2: DEVICE TRUST (pairing_v2.py)
  Persistent 30-day trust, auto re-pair without code entry
  Device public key stored in DB, verified on reconnect

Layer 3: AUTHENTICATION
  Bearer token on every request, SHA-256 hash verified
  Token rotation every 30 minutes

Layer 4: RISK CLASSIFICATION (risk.py)
  0: read-only  1: open  2: modify  3: sensitive  4: critical  5: dangerous

Layer 5: PERMISSION ENGINE (permissions.py)
  risk >= 3 → phone approval required

Layer 6: APPROVAL FLOW (manager.py)
  asyncio.Future-based blocking, 300s timeout, emergency cancel

Layer 7: VAULT ENCRYPTION (vault.py)
  AES-256-GCM + Argon2id (preferred) or PBKDF2 (fallback)
  5-min session, memory wipe on lock, per-unlock key cache

Layer 8: BIOMETRIC CHALLENGE (pairing_v2.py)
  Challenge-response for vault unlock (Windows Hello / phone biometric)

Layer 9: LOG REDACTION (redactor.py)
  Regex: passwords, tokens, CC, SSN, email — now wired as logging filter

Layer 10: QUARANTINE (file_tools.py)
  All deletes → quarantine (reversible), permanent delete special approval

Layer 11: EMERGENCY STOP (router.py + main.py)
  Always available, cancels all pending, cannot be disabled

Layer 12: SANITIZED EXECUTION
  No shell=True for app launch or command execution
  Dangerous file extensions blocked in downloads
  Protected paths checked before file operations
```
